# Contributing to Paintball Tactical Editor

## Как работать над проектом

### 1. Спринты

Каждый спринт имеет:
- Чёткую цель
- Список задач
- Критерии готовности

**Важно:** Не начинаем следующий спринт без одобрения архитектора.

---

### 2. Создание задач

Каждая задача должна быть:
- Конкретной
- Измеримой
- Достижимой

**Пример:**
- ❌ "Улучшить редактор"
- ✅ "Реализовать загрузку изображений PNG"

---

### 3. Architecture Decision Records (ADR)

Каждое архитектурное решение фиксируется в ADR.

**Структура ADR:**
1. Название и дата
2. Статус (Принято/Отклонено/Заменено)
3. Контекст — почему нужно решение
4. Решение — что решили
5. Альтернативы — что рассматривали
6. Последствия — что изменится

**Хранение:** `docs/decisions/ADR-XXXX-Nazvanie.md`

---

### 4. Ветки (Git)

- `main` — стабильная версия
- `sprint/X` — ветка для спринта
- `feature/XXX` — ветка для фичи

---

### 5. Коммиты

**Формат:**

**Типы:**
- `feat` — новая функциональность
- `fix` — исправление бага
- `docs` — документация
- `refactor` — рефакторинг
- `test` — тесты
- `chore` — служебные задачи

---

### 6. Отчёты

Каждый спринт завершается отчётом.

**Шаблон:** `docs/templates/SPRINT_REPORT_TEMPLATE.md`

---

### 7. Код

**Стиль:** Следуем `AI/CODING_RULES.md`

**Язык:** GDScript

**Тесты:** Пишем тесты для нового кода
